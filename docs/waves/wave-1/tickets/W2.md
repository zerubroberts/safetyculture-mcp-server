# TICKET W2: Issues and investigations toolsets

Repo: safetyculture-mcp, an open-source MCP server for Mitti (formerly SafetyCulture). Spec: docs/SPEC.md.

## FILES ALLOWED
src/toolsets/issues.ts, src/toolsets/investigations.ts, test/toolsets/issues.test.ts, test/toolsets/investigations.test.ts

## API SECTIONS
docs/api-index.md sections: Issues, Investigations, OSHA. Issues used to be called Incidents; paths use /incidents/. Run `node scripts/api-ref.mjs <slug>` for every endpoint you call.

## GOAL
In `src/toolsets/issues.ts` (export `issuesTools`):
- `sc_list_issues` (read, core, untrusted): filters status, priority, category_ids, site_ids, period (created or occurred), assignee; limit/page_token. Rows id, ref, title, category, status, priority, site, occurred_at, created_at, due_at, assignees, `link` (links.issue). Include counts by status and category.
- `sc_get_issue` (read, core, untrusted): full detail including questions and answers and linked inspection.
- `sc_count_issues`, `sc_list_issue_categories`, `sc_get_issue_timeline` (untrusted), `sc_get_issue_report` (PDF + web report link) (all read).
- `sc_create_issue` (write, core): title, category, description, priority, site, occurred_at, due_at, assignees, reason. Use the current Create Issue endpoint, not the legacy one.
- `sc_update_issue` (write, core, patch style like sc_update_action): title, description, status, priority, due_at, occurred_at, site, category, asset, add/remove assignees. Per-field success/failure.
- `sc_comment_on_issue` (write). `sc_delete_issues` (destructive, plan lists titles).

In `src/toolsets/investigations.ts` (export `investigationsTools`):
- `sc_list_investigations` (read, untrusted), `sc_get_investigation` (read: details plus counts and lists of linked inspections, actions, issues, media), `sc_create_investigation` (write), `sc_update_investigation` (write, patch style).
- `sc_list_osha_cases`, `sc_get_osha_case`, `sc_list_osha_establishments` (read). OSHA records are injury data: untrusted, minimal projections, free-text medical fields only with an explicit `include_details: true`.
