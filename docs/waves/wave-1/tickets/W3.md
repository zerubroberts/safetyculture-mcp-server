# TICKET W3: Assets, sites and people toolsets

Repo: safetyculture-mcp, an open-source MCP server for Mitti (formerly SafetyCulture). Spec: docs/SPEC.md.

## FILES ALLOWED
src/toolsets/assets.ts, src/toolsets/sites.ts, src/toolsets/people.ts, test/toolsets/assets.test.ts, test/toolsets/sites.test.ts, test/toolsets/people.test.ts

## API SECTIONS
docs/api-index.md sections: Assets, Directory (Sites), Structures, Users, Groups, Roles. Run `node scripts/api-ref.mjs <slug>` for every endpoint you call.

## GOAL
In `src/toolsets/assets.ts` (export `assetsTools`):
- `sc_list_assets` (read: filters type, site, state, text; limit/page_token), `sc_get_asset` (read, with field values), `sc_find_asset` (read: by code, or by field value).
- `sc_list_asset_types`, `sc_list_asset_fields` (read).
- `sc_list_maintenance_programs` (read), `sc_get_asset_maintenance` (read: maintenance details + service history for one asset), `sc_maintenance_status_counts` (read).
- `sc_create_asset` (write), `sc_update_asset` (write, patch: field values, location, site), `sc_archive_asset` (destructive).

In `src/toolsets/sites.ts` (export `sitesTools`):
- `sc_list_sites` (read, core): sites/folders with parent, text search; rows id, name, parent id, level label.
- `sc_get_site` (read), `sc_site_tree` (read: nested hierarchy capped by depth), `sc_list_site_members` (read).
- `sc_create_site` (write), `sc_add_site_members` (write).

In `src/toolsets/people.ts` (export `peopleTools`):
- `sc_search_users` (read, core): by name/email text, active, group; rows id, name, email, active, seat type, last seen. (The registry pseudonymises emails by default: do not work around it.)
- `sc_get_user`, `sc_list_groups`, `sc_list_group_members`, `sc_list_permission_sets` (read).
- `sc_add_user_to_group` (write), `sc_remove_user_from_group` (destructive).
- Do NOT implement user creation, deactivation or permission-set assignment (out of scope for security).
