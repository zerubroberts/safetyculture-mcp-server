## GOAL
1. `src/cache/feeds.ts`: a `FEEDS: Record<FeedName, FeedDef>` with the exact path, key, incremental parameter, watermark field and safe page size for every FeedName in contract.ts, each verified with api-ref (schedules use the current `/scheduling/v1/feed/*` feeds; credentials, contractor companies, training course progress and investigations are under feedservice_*). Feeds without an `id` (group_users, site_members, action_assignees, schedule_assignees) need composite keys. Include archived and incomplete inspections where the feed allows (analytics needs both).
2. `src/cache/store.ts`: `CacheWriter` on `node:sqlite` (`DatabaseSync`). One file per organisation at `<config.dataDir>/cache/<org-fingerprint>.sqlite` (fingerprint = first 16 hex of sha256 of organisation_id from `/accounts/user/v1/user:WhoAmI`), created with mode 0600. Tables `feed_<name>(id TEXT PRIMARY KEY, modified_at TEXT, data TEXT)` + `sync_state`. Upserts in a transaction. Suppress only Node's SQLite ExperimentalWarning (not other warnings).
3. `src/cache/sync.ts`: incremental sync per feed: watermark = max modified field; next run uses `modified_after = watermark - 10 minutes` overlap; upsert dedupes. First run is a full pull bounded by `maxRows` (default 50,000 per feed) and reports `complete: false` when capped. If a feed returns HTTP 400 for page size, retry with 100. Stop and record `last_error` on a repeating cursor (client.collectFeed reports `stuck`). Feeds that 403/404 (module not licensed) are recorded as unavailable with the API message, not as errors that abort other feeds. Never log row contents.
4. `src/cache/index.ts`: real `createCacheProvider(ctx)`: lazy open, `ensure(feeds, {maxAgeMinutes=60})` syncs stale feeds then returns the reader. Expose a `syncFeeds` function for the sc_sync tool.
5. `src/toolsets/feeds.ts` (export `feedsTools`):
   - `sc_list_feeds` (read): feeds, what each contains, cached rows, freshness.
   - `sc_read_feed` (read, untrusted): one page of a live feed with modified_after and limit (raw rows, capped).
   - `sc_sync` (read, core; it only writes the local cache): feeds (default: inspections, inspection_items, actions, issues, sites, users, templates, schedules, schedule_occurrences), `full` flag; returns per-feed SyncReport and total duration.
   - `sc_sync_status` (read, core): per-feed status + cache file path + size.
   - `sc_export_dataset` (read, core; writes a local file): export a cached feed or a filtered subset (period on a date field, site, template) to CSV or JSONL in `config.exportDir`; return path, row count, columns. CSV must escape properly and neutralise spreadsheet formula injection (cells starting with = + - @ tab CR get a leading apostrophe). Flatten nested JSON columns to JSON strings.
   - `sc_query_cache` (read): read-only SQL over the cache for analysts. Single SELECT/WITH statement only; reject ATTACH, PRAGMA, multiple statements, writes; open a separate read-only connection (`readOnly: true`); row cap 500; time cap.
6. `src/exports/bi-bundle.ts` + `src/toolsets/integrations.ts` (export `integrationsTools`):
   - `sc_export_bi_bundle` (read; writes local files): a folder with a star schema as CSV: fact_inspections, fact_inspection_items (failed flag, score), fact_actions, fact_issues, fact_schedule_occurrences, dim_sites, dim_templates, dim_users (pseudonymised per config.pii), dim_date; plus `manifest.json` (grains, keys, relationships, row counts, as_of), a Power BI Power Query M script that loads the folder and declares relationships in comments, a Qlik Sense load script (`.qvs`), and a README.md explaining how to load it in Power BI, Qlik and Excel. Row counts in the manifest must equal the CSV row counts (test it).
   - `sc_post_to_chat` (write): post a short Markdown message to a Slack or Microsoft Teams incoming webhook chosen BY NAME from the env var `SC_NOTIFY_WEBHOOKS` (JSON object name -> https URL). Never accept a raw URL from the model. Read the env via `process.env` inside the tool. Message length cap 3,000 chars. Slack payload `{text}`; Teams payload: a simple MessageCard or the documented Workflows format (pick one, document it).
